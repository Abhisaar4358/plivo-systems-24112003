Flaky Network Transport

This submission implements a small real-time UDP transport for 160-byte frames generated every 20 ms. Its goal is to deliver correct frames before their playout deadlines despite loss, random delay, duplication, and reordering, while keeping total relay traffic below twice the raw stream.

Architecture

harness source --47010--> sender --47001--> hostile relay --47002--> receiver --47020--> harness player
                                      ^                                  |
                                      +------ feedback ports reserved ----+

The sender and receiver are the only modified programs. The Python harness and relay are not changed. Feedback ports are reserved by the wire protocol but are unused in the current design because proactive recovery is more useful than a round-trip retransmission for short deadlines.

Wire format and protection

Every packet crossing the relay is 172 bytes: a 12-byte protocol header followed by a 160-byte body. The header carries a magic byte, version, packet type, position in a block, big-endian base sequence number, and block size. A data body is the original frame payload; a parity body is the bytewise XOR of the two data bodies in its block.

frame 2k       -- data packet -->
frame 2k + 1   -- data packet -->
frame 2k XOR frame 2k + 1 -- parity packet -->

If exactly one data packet is absent but parity and the other data packet arrive, the receiver recreates it with XOR and forwards the original required sequence + 160-byte payload harness format. Received data is forwarded immediately; a bounded 16-block ring retains enough state to handle reordered packets and duplicates without unbounded memory growth.

Trade-offs

Sending one parity packet for every two data packets creates approximately 1.61x relay overhead, leaving room beneath the 2x limit. It reduces the maximum wait for parity to one 20 ms frame interval and makes a single loss in a pair recoverable. It cannot recover two unavailable packets in the same protected pair, so burst loss and low deadlines remain the primary limitations.
